3. Что такое Search Console и Bing: аккаунты без путаницы

Google Search Console, сокращённо GSC, — бесплатный кабинет владельца сайта. Он показывает, как Google обнаруживает страницы и какие поисковые запросы приводят людей. Для входа подходит ваш Google-аккаунт, например тот, которым вы пользуетесь для Gmail. Новая почта только ради GSC не обязательна. Регистрация не требуется для самого появления в поиске, но даёт инструменты диагностики. О сервисе.

Bing Webmaster Tools, сокращённо BWT, — аналогичный кабинет Microsoft для Bing. На странице входа выберите доступный способ авторизации, которым сможете пользоваться постоянно. Это отдельный сервис даже при входе через Google. Он не управляет позициями в Google. О возможностях BWT.

4. Подключаем Google: конкретные шаги для вашего домена

4.1. Выберите правильный тип ресурса

Рекомендую создать два ресурса в одном кабинете:

Тип Что ввести Зачем
Доменный ресурс / Domain kolosei.com Общая картина домена, включая поддомены
Ресурс с префиксом URL / URL prefix https://kolosei.com/ Ежедневный отчёт именно по сайту-витрине

Доменный ресурс подтверждается через DNS. Префикс ограничивает данные конкретным началом адреса. Дополнительный https://linguistpro.kolosei.com/ можно создать позже для отдельной работы с приложением. Не складывайте показатели доменного и вложенного ресурсов: одни и те же данные пересекаются. Типы ресурсов.

4.2. Получите запись подтверждения

  1. Откройте Search Console и войдите.
  2. Откройте список ресурсов в левом верхнем углу. Выберите «Добавить ресурс / Add property».
  3. В варианте «Домен / Domain» введите kolosei.com без https://, без /ru/ и без завершающей косой черты.
  4. Продолжите. Если предлагается ручная DNS-проверка, скопируйте TXT-значение, выданное именно вашим кабинетом.
  5. Оставьте эту вкладку открытой и перейдите в Cloudflare в соседней вкладке.

Значение выглядит примерно как google-site-verification=.... Это лишь форма записи: многоточие из руководства использовать нельзя. Google должен увидеть выданное вам значение. Проверочный токен подтверждает владение, а не улучшает позиции. Подтверждение владения.

4.3. Добавьте TXT в Cloudflare

В этой сессии DNS-проверка показала NS-серверы Cloudflare. Поэтому ниже приведён основной путь для текущей конфигурации. Если после переезда DNS будет обслуживаться другим провайдером, запись надо добавлять у него.

  1. Откройте Cloudflare под аккаунтом, которому принадлежит домен.
  2. Выберите зону kolosei.com. Нужен раздел домена, а не настройки проекта Pages.
  3. Перейдите в DNS → Records / Записи.
  4. Нажмите Add record / Добавить запись.
  5. Заполните поля по таблице.
  6. Сохраните. Вернитесь в GSC и нажмите Verify / Подтвердить.
Поле Cloudflare Значение
Type / Тип TXT
Name / Имя @ — корень домена; интерфейс может показать kolosei.com
Content / Содержимое Полная строка, выданная Google
TTL Auto, если доступно

Добавляйте отдельную TXT-запись. Не заменяйте почтовые SPF/DKIM-записи и не меняйте A, AAAA, CNAME, MX или NS. Настройки проксирования HTTP для TXT не нужны. В данном случае задача — подтвердить владение, а не перенастроить сайт. Добавление DNS-записей Cloudflare.

Если подтверждение пока не удалось: проверьте домен и скопированное значение, затем повторите позже. DNS может распространяться с задержкой. Не создавайте десять одинаковых записей. После успеха сохраните запись: Google может проверять её снова. Если в Cloudflare не виден домен, вероятно, открыт другой аккаунт или нет прав; не переносите DNS ради этой проверки.

4.4. Добавьте ресурс витрины

После подтверждения домена снова выберите Add property, затем URL prefix, введите https://kolosei.com/. Подтверждённое владение родительским доменом обычно позволяет подтвердить вложенный ресурс автоматически. Если кабинет требует дополнительное действие, следуйте его указаниям. Для повседневных измерений выберите именно этот ресурс. Наследование подтверждения.

4.5. Если доступа к DNS пока нет

Можно начать с URL-prefix и метода HTML-файла. Скачайте файл, выданный GSC; разработчик кладёт его без изменений в E:/projects/kolosei-hub/public/, публикует и проверяет публичный адрес файла. Затем вы нажимаете Verify. Имя файла и содержимое нельзя придумывать. Это подтверждает URL-prefix, но не заменяет DNS-подтверждение всего домена. Не используйте временный preview-адрес Cloudflare вместо kolosei.com. Метод HTML-файла.

5. Отправляем sitemap в Google и понимаем результат

5.1. Что вы отправляете

Sitemap — список адресов для поискового робота. Наш sitemap-index.xml содержит ссылку на sitemap-0.xml, а тот — 34 канонических адреса сайта. Это нормальная структура «указатель → список». Число 34 относится ко всему сайту-витрине, включая другие проекты и служебные страницы. Это не количество текстов LinguistPro и не число уже проиндексированных страниц.

8 сентября публичные Node HTTP-запросы повторно получили 200 для обоих sitemap, robots.txt, фактов JSON и русской главной. Указатель уже приведён в robots.txt. Не нужно создавать ещё одну карту вручную.

5.2. Последовательность в кабинете

  1. В GSC выберите https://kolosei.com/.
  2. В левом меню найдите «Индексирование → Файлы Sitemap / Indexing → Sitemaps».
  3. В поле добавления введите sitemap-index.xml, если начало https://kolosei.com/ уже показано перед полем. Если поле ожидает полный адрес, вставьте https://kolosei.com/sitemap-index.xml.
  4. Нажмите «Отправить / Submit».
  5. Откройте появившуюся строку и запишите дату, статус и число обнаруженных страниц, когда оно появится.

Проверьте итоговый адрес: в нём не должно быть дважды https://kolosei.com/. Для отправки через этот отчёт нужны права владельца. Официальный отчёт Sitemap.

Успешная отправка не гарантирует индексацию всех адресов. При индексной карте смотрите также вложенную карту: разные экраны могут показывать число карт и число страниц. Не требуйте, чтобы любая цифра на экране немедленно стала 34. Как трактовать отчёт.

После обычного обновления сайта: новый sitemap собирается автоматически. Не удаляйте и не отправляйте ту же карту ежедневно. Меняйте содержимое сайта, проверяйте карту после публикации и наблюдайте её повторное чтение.

Как проверить один адрес

  1. Вставьте полный URL в верхнюю строку «Проверка URL / URL inspection».
  2. Прочитайте статус версии, известной Google.
  3. Если страница недавно изменена, нажмите «Проверить опубликованную страницу / Test live URL».
  4. Посмотрите, разрешены ли сканирование и индексирование, доступна ли страница.
  5. Для новой или существенно исправленной страницы при необходимости нажмите «Запросить индексирование / Request indexing».

8. Как измерять результат: словарь и простая воронка

Основной ориентир на первый период: растёт число целевых поисковых визитов и доля посетителей, которые переходят в продукт. Когда появится измерение приложения — добавляем первое полезное действие и возвращение к занятиям.

Показатель Простыми словами Где взять
Показы / Impressions Как часто результат сайта показывался в поиске GSC или BWT
Клики / Clicks Сколько переходов совершено из результатов поиска GSC или BWT
CTR Клики, делённые на показы, в процентах GSC/BWT или расчёт
Средняя позиция Усреднённое положение результата в наблюдавшихся показах GSC; анализировать в разрезах
Сеансы / Sessions Посещения, сгруппированные системой аналитики После установки аналитики
Переход в продукт Нажатие ссылки, ведущей в Студию или Зал Специальное событие сайта, пока не подключено
Активация Первое заранее определённое полезное действие в приложении Отдельное измерение приложения
Возвращение Повторная полезная работа той же когорты Отдельное измерение приложения или добровольное исследование

Определения поисковых кликов, показов, CTR и средней позиции приведены в справке Performance. Средняя позиция всего сайта может ухудшиться, когда появились новые показы по новым запросам; это не обязательно означает ухудшение старых страниц.

Пример расчёта — условные числа, не данные вашего сайта

За 28 дней получено 1000 показов и 40 кликов. CTR = 40 / 1000 × 100% = 4%. Аналитика сайта за тот же период зафиксировала 36 органических сеансов, из которых в 9 был переход в продукт. Доля сеансов с переходом = 9 / 36 × 100% = 25%.

40 кликов GSC и 36 сеансов аналитики не обязаны совпадать: это разные системы и способы подсчёта; дополнительно влияют согласие, блокировщики, загрузка страницы, часовые пояса и фильтры. Нельзя объявить «10% пользователей потерялись» только из этого различия.

Если событий перехода 12, но они произошли в 9 сеансах, для доли сеансов берите 9, а не 12. Один человек мог нажать несколько раз. Если знаменатель равен нулю, пишите «не рассчитывается». При изменении с 0 до 5 кликов пишите «+5 кликов», а не «рост на бесконечность».

Три панели вместо одного большого числа

  • Техника: доступность ключевых URL, ошибки, лабораторная скорость, полевые метрики при наличии.
  • Привлечение: поисковые показы, клики, видимые небрендовые запросы, внешние переходы, ИИ-цитирование.
  • Польза: сеансы с переходом в продукт, завершённое первое действие, возвращения.

Рост технических баллов без движения второй и третьей панелей — поддержание качества, а не доказанное продвижение.

Поэтому сейчас «число переходов в Зал неизвестно», а не «переходов ноль». Search Console наблюдает выдачу Google и клики из неё; он не считает нажатие вашей кнопки «Начать с готового текста» после открытия сайта.

Прямое чтение URL, брендовый тест и тест обнаружения считайте отдельно. Если запускаете повторно, заранее задайте число повторов и сохраните все результаты, а не только удачные.

  • Есть хотя бы один подтверждённый пользовательский сценарий и понятное улучшение по обратной связи.

После первого полного периода поставьте численную цель на следующий. Пример, не прогноз: если было 40 целевых кликов и 8 органических сеансов с переходом, рабочая цель может быть 50 кликов и 10 таких сеансов при сохранении качества аудитории. Показатели кликов и сеансов ведите раздельно. При малых числах такой рост — сигнал для дальнейшей проверки, а не статистически доказанная причинность.

Если за 56 дней почти нет показов, сначала проверьте индексацию, попадание в потребность и содержание страниц. Если показы есть, а кликов мало — анализируйте запрос, заголовок и позицию. Если переходы есть, а пользы нет — исследуйте приложение и первый сценарий. Дальнейшие действия зависят от места потери.

18. Нагрузка, расходы и помощь специалиста

Для старта достаточно бесплатных поисковых кабинетов, PageSpeed и обычной личной таблицы. Не покупайте большой SEO-сервис до того, как понимаете, какого ответа не хватает в бесплатных инструментах.

Реалистичный рабочий ритм для одного владельца: 30 минут на отчёт, 1–2 часа на полезное улучшение материала и до часа на обратную связь/распространение в неделю. Это план нагрузки, а не норматив. Если времени мало, делайте один хороший материал раз в две недели и сохраняйте регулярность измерения.

Разработчик нужен для подключения событий, технических ошибок, изменений шаблонов, редиректов и публикации. Преподаватель или компетентный редактор — для языковой и педагогической проверки. SEO-специалист становится полезен, когда уже есть данные и конкретная задача: например, страницы проиндексированы, но релевантных показов мало.

Просите у специалиста конкретные действия, доказательства, отчёт по вашим целевым URL и понятную метрику. Проверяйте, что аккаунты принадлежат вам и результаты сохраняются. Не принимайте «подняли внутренний SEO-score» за единственное подтверждение пользы работы.
