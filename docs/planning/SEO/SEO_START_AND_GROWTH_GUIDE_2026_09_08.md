# Как продвигать LinguistPro и измерять результат

Практическое руководство владельца kolosei.com · 8 сентября 2026 года

**Начните с разделов 1–7.** Они помогут подключить поисковые кабинеты и отправить sitemap. Затем настройте измерение результата по разделам 8–10 и работайте по календарю из раздела 15. Не нужно осваивать весь документ за один вечер.

Это рабочий план для человека, который впервые занимается продвижением. Технические факты сверены с сайтом и репозиторием; инструкции сервисов — с официальными источниками на дату документа. Названия кнопок могут отличаться из-за языка и обновлений интерфейса. Предлагаемые сроки и целевые показатели — наш план работы, а не обещания поисковых систем.

**Что уже есть:** опубликованный сайт с хорошей технической основой. **Что предстоит:** открыть измерения, убедиться в индексации, найти востребованные темы и превратить внимание в использование продукта. В рамках этого документа аккаунты, DNS и аналитика не изменялись.

## 1. Ваш первый результат: семь понятных действий

На первую настройку запланируйте два спокойных вечера по 45–60 минут. Ожидание проверки DNS и появления отчётов в это время не входит.

- [ ] Войти в Google Search Console своим постоянным Google-аккаунтом.
- [ ] Подтвердить домен `kolosei.com` через DNS-запись Cloudflare.
- [ ] Добавить отдельный ресурс `https://kolosei.com/`, чтобы видеть именно сайт-витрину.
- [ ] Отправить `https://kolosei.com/sitemap-index.xml` в Google и записать статус.
- [ ] Проверить главную и две продуктовые страницы через «Проверку URL».
- [ ] Добавить сайт в Bing Webmaster Tools и проверить отправку того же sitemap.
- [ ] Записать исходные показатели и назначить еженедельные 30 минут для наблюдения.

**Критерий завершения первого этапа:** вы умеете открыть правильный ресурс, видите подтверждённое владение, знаете статус sitemap и понимаете, где смотреть поисковые показы и клики. Если данных пока нет, честный результат — «кабинет подключён, данные ещё не накоплены».

### Четыре разных уровня успеха

1. **Сайт исправен:** быстро открывается, читается на телефоне, ссылки работают.
2. **Сайт обнаружен:** поисковик нашёл адреса и включил важные страницы в индекс.
3. **Сайт привлекает нужных людей:** есть показы и клики по подходящим запросам.
4. **Люди получают пользу:** переходят в Зал или Студию и совершают первое полезное действие.

Нельзя заменить четвёртый уровень красивой оценкой первого. Но плохая работа страницы способна помешать всем остальным.

## 3. Что такое Search Console и Bing: аккаунты без путаницы

**Google Search Console, сокращённо GSC, — бесплатный кабинет владельца сайта.** Он показывает, как Google обнаруживает страницы и какие поисковые запросы приводят людей. Для входа подходит ваш Google-аккаунт, например тот, которым вы пользуетесь для Gmail. Новая почта только ради GSC не обязательна. Регистрация не требуется для самого появления в поиске, но даёт инструменты диагностики. [О сервисе](https://support.google.com/webmasters/answer/9128668?hl=en).

**Bing Webmaster Tools, сокращённо BWT, — аналогичный кабинет Microsoft для Bing.** На странице входа выберите доступный способ авторизации, которым сможете пользоваться постоянно. Это отдельный сервис даже при входе через Google. Он не управляет позициями в Google. [О возможностях BWT](https://blogs.bing.com/webmaster/June-2025/Start-Using-Bing-Webmaster-Tools-to-Improve-Your-Site-Visibility).

| Название | Простое объяснение | Нужно ли сейчас |
| --- | --- | --- |
| Google-аккаунт | Ваша личность для входа в сервисы Google | Да |
| Ресурс / Property в GSC | Конкретный сайт или часть сайта, которую вы наблюдаете | Да |
| Cloudflare-аккаунт | Кабинет, где управляется DNS вашего домена | Да, для выбранного способа подтверждения |
| Bing Webmaster Tools | Второй поисковый кабинет | Да, после Google |
| Google Analytics 4 / GA4 | Система измерения действий посетителей после открытия сайта | Второй этап, отдельная настройка |
| Google Ads | Платная реклама | Не нужна для первого этапа |
| Google Cloud / Gemini API | Облачные вычисления и модельные API | Для sitemap и GSC не нужны |
| ChatGPT / Claude / Gemini | Пользовательские ИИ-сервисы | Для контрольных проверок цитирования, не для отправки sitemap в GSC |

Выберите аккаунт, который останется у вас надолго. Сохраните способ восстановления и включите двухэтапный вход. Подрядчику позднее выдаётся доступ через настройки кабинета; передавать ему пароль от основной почты не требуется. Не записывайте пароли, резервные коды и личные экспортированные данные в этот публичный репозиторий.

### Два адреса — две разные задачи

`kolosei.com` — сайт, который объясняет продукт и привлекает людей. `linguistpro.kolosei.com` — само приложение. Один удачный визит на главную ещё не означает, что человек начал читать. Поэтому отдельно наблюдаем продвижение витрины и использование приложения.

## 4. Подключаем Google: конкретные шаги для вашего домена

### 4.1. Выберите правильный тип ресурса

Рекомендую создать **два ресурса в одном кабинете**:

| Тип | Что ввести | Зачем |
| --- | --- | --- |
| Доменный ресурс / Domain | `kolosei.com` | Общая картина домена, включая поддомены |
| Ресурс с префиксом URL / URL prefix | `https://kolosei.com/` | Ежедневный отчёт именно по сайту-витрине |

Доменный ресурс подтверждается через DNS. Префикс ограничивает данные конкретным началом адреса. Дополнительный `https://linguistpro.kolosei.com/` можно создать позже для отдельной работы с приложением. Не складывайте показатели доменного и вложенного ресурсов: одни и те же данные пересекаются. [Типы ресурсов](https://support.google.com/webmasters/answer/34592?hl=en).

### 4.2. Получите запись подтверждения

1. Откройте [Search Console](https://search.google.com/search-console/) и войдите.
2. Откройте список ресурсов в левом верхнем углу. Выберите **«Добавить ресурс / Add property»**.
3. В варианте **«Домен / Domain»** введите `kolosei.com` без `https://`, без `/ru/` и без завершающей косой черты.
4. Продолжите. Если предлагается ручная DNS-проверка, скопируйте TXT-значение, выданное именно вашим кабинетом.
5. Оставьте эту вкладку открытой и перейдите в Cloudflare в соседней вкладке.

Значение выглядит примерно как `google-site-verification=...`. Это лишь форма записи: многоточие из руководства использовать нельзя. Google должен увидеть выданное вам значение. Проверочный токен подтверждает владение, а не улучшает позиции. [Подтверждение владения](https://support.google.com/webmasters/answer/9008080?hl=en).

### 4.3. Добавьте TXT в Cloudflare

В этой сессии DNS-проверка показала NS-серверы Cloudflare. Поэтому ниже приведён основной путь для текущей конфигурации. Если после переезда DNS будет обслуживаться другим провайдером, запись надо добавлять у него.

1. Откройте [Cloudflare](https://dash.cloudflare.com/) под аккаунтом, которому принадлежит домен.
2. Выберите зону **kolosei.com**. Нужен раздел домена, а не настройки проекта Pages.
3. Перейдите в **DNS → Records / Записи**.
4. Нажмите **Add record / Добавить запись**.
5. Заполните поля по таблице.
6. Сохраните. Вернитесь в GSC и нажмите **Verify / Подтвердить**.

| Поле Cloudflare | Значение |
| --- | --- |
| Type / Тип | `TXT` |
| Name / Имя | `@` — корень домена; интерфейс может показать `kolosei.com` |
| Content / Содержимое | Полная строка, выданная Google |
| TTL | `Auto`, если доступно |

Добавляйте отдельную TXT-запись. Не заменяйте почтовые SPF/DKIM-записи и не меняйте A, AAAA, CNAME, MX или NS. Настройки проксирования HTTP для TXT не нужны. В данном случае задача — подтвердить владение, а не перенастроить сайт. [Добавление DNS-записей Cloudflare](https://developers.cloudflare.com/dns/manage-dns-records/how-to/create-dns-records/).

**Если подтверждение пока не удалось:** проверьте домен и скопированное значение, затем повторите позже. DNS может распространяться с задержкой. Не создавайте десять одинаковых записей. После успеха сохраните запись: Google может проверять её снова. Если в Cloudflare не виден домен, вероятно, открыт другой аккаунт или нет прав; не переносите DNS ради этой проверки.

### 4.4. Добавьте ресурс витрины

После подтверждения домена снова выберите **Add property**, затем **URL prefix**, введите `https://kolosei.com/`. Подтверждённое владение родительским доменом обычно позволяет подтвердить вложенный ресурс автоматически. Если кабинет требует дополнительное действие, следуйте его указаниям. Для повседневных измерений выберите именно этот ресурс. [Наследование подтверждения](https://support.google.com/webmasters/answer/9008080?hl=en).

### 4.5. Если доступа к DNS пока нет

Можно начать с URL-prefix и метода HTML-файла. Скачайте файл, выданный GSC; разработчик кладёт его без изменений в `E:/projects/kolosei-hub/public/`, публикует и проверяет публичный адрес файла. Затем вы нажимаете Verify. Имя файла и содержимое нельзя придумывать. Это подтверждает URL-prefix, но не заменяет DNS-подтверждение всего домена. Не используйте временный preview-адрес Cloudflare вместо `kolosei.com`. [Метод HTML-файла](https://support.google.com/webmasters/answer/9008080?hl=en).

## 5. Отправляем sitemap в Google и понимаем результат

### 5.1. Что вы отправляете

Sitemap — список адресов для поискового робота. Наш `sitemap-index.xml` содержит ссылку на `sitemap-0.xml`, а тот — 34 канонических адреса сайта. Это нормальная структура «указатель → список». Число 34 относится ко всему сайту-витрине, включая другие проекты и служебные страницы. Это не количество текстов LinguistPro и не число уже проиндексированных страниц.

8 сентября публичные Node HTTP-запросы повторно получили 200 для обоих sitemap, `robots.txt`, фактов JSON и русской главной. Указатель уже приведён в `robots.txt`. Не нужно создавать ещё одну карту вручную.

### 5.2. Последовательность в кабинете

1. В GSC выберите **`https://kolosei.com/`**.
2. В левом меню найдите **«Индексирование → Файлы Sitemap / Indexing → Sitemaps»**.
3. В поле добавления введите `sitemap-index.xml`, если начало `https://kolosei.com/` уже показано перед полем. Если поле ожидает полный адрес, вставьте `https://kolosei.com/sitemap-index.xml`.
4. Нажмите **«Отправить / Submit»**.
5. Откройте появившуюся строку и запишите дату, статус и число обнаруженных страниц, когда оно появится.

Проверьте итоговый адрес: в нём не должно быть дважды `https://kolosei.com/`. Для отправки через этот отчёт нужны права владельца. [Официальный отчёт Sitemap](https://support.google.com/webmasters/answer/7451001?hl=ru).

### 5.3. Как читать статусы

| Что видно | Как трактовать | Ваше действие |
| --- | --- | --- |
| Success / Успешно | Карта прочитана и обработана | Сохранить результат и перейти к проверке URL |
| Couldn't fetch / Не удалось получить | Поисковик не смог прочитать карту | Проверить полный адрес, публичное открытие и сообщения отчёта |
| Ошибка формата | Проблема с XML или указанными адресами | Передать разработчику точный текст ошибки |
| Найдено 0 или пока нет данных | Данные ещё не готовы либо требуется разбор ошибки | Не объявлять провал сразу; проверить статус обработки |

Успешная отправка не гарантирует индексацию всех адресов. При индексной карте смотрите также вложенную карту: разные экраны могут показывать число карт и число страниц. Не требуйте, чтобы любая цифра на экране немедленно стала 34. [Как трактовать отчёт](https://support.google.com/webmasters/answer/7451001?hl=ru).

**После обычного обновления сайта:** новый sitemap собирается автоматически. Не удаляйте и не отправляйте ту же карту ежедневно. Меняйте содержимое сайта, проверяйте карту после публикации и наблюдайте её повторное чтение.

### Как проверить один адрес

1. Вставьте полный URL в верхнюю строку **«Проверка URL / URL inspection»**.
2. Прочитайте статус версии, известной Google.
3. Если страница недавно изменена, нажмите **«Проверить опубликованную страницу / Test live URL»**.
4. Посмотрите, разрешены ли сканирование и индексирование, доступна ли страница.
5. Для новой или существенно исправленной страницы при необходимости нажмите **«Запросить индексирование / Request indexing»**.
6. Запишите результат; переходите к следующему адресу без многократного повторения одного запроса.

«Live test прошёл» означает техническую доступность сейчас. «Страница есть в Google» относится к индексу. Поле **Google-selected canonical** в индексных данных показывает, какой адрес выбрал Google; live test не предсказывает этот выбор. Запрос индексирования не обещает срок или место. [URL Inspection](https://support.google.com/webmasters/answer/9012289?hl=en).

### Что делать с исключёнными страницами

| Ситуация | Первое разумное действие |
| --- | --- |
| Обнаружена, но пока не проиндексирована | Проверить внутренние ссылки и дать время обработке |
| Просканирована, но не проиндексирована | Проверить полезность, самостоятельность содержания и дубли |
| Дубликат / другая каноническая страница | Проверить выбранный Google адрес и смысл дубля |
| Страница с переадресацией | Для старого адреса это может быть ожидаемо; проверять конечный URL |
| `noindex` на нужной публичной странице | Исправить причину в шаблоне, затем проверить живую страницу |
| 403 / 5xx / ошибка загрузки | Разработчику проверить сервер и правила защиты |

Не все исключения требуют исправления. Старый `/projects/` перенаправляется на `/products/`; добиваться отдельной индексации старого дубля не нужно. [Отчёт об индексировании](https://support.google.com/webmasters/answer/7440203?hl=en).

Техническое наблюдение этой сессии: Python `urllib` получил 403 на запрос карты, тогда как Node получил 200. Это не доказывает блокировку настоящего Googlebot. Поэтому ваша первая проверка через URL Inspection особенно полезна: она даст доказательство со стороны Google. Если там тоже ошибка, нужно исследовать Cloudflare Security Events и конкретное правило; отключать защиту всего домена не следует.

## 7. Подключаем Bing и разбираемся с IndexNow

### 7.1. Основной путь — импорт из Google

1. Откройте [Bing Webmaster Tools](https://www.bing.com/webmasters/) и войдите.
2. Выберите добавление сайта и вариант **Import from Google Search Console**.
3. Авторизуйте тот Google-аккаунт, в котором подтверждён `kolosei.com`.
4. Посмотрите запрашиваемые разрешения и список ресурсов.
5. Выберите ресурс витрины `https://kolosei.com/`, если он представлен отдельно, и выполните импорт.
6. Если Bing нормализует или группирует ресурсы, проверьте, какой сайт выбран вверху кабинета.

Импорт может перенести подтверждение и сведения о sitemap. Если вы не хотите связывать кабинеты, выберите ручное добавление сайта и один из предложенных Bing методов проверки. [Добавление и проверка сайта](https://www.bing.com/webmasters/help/add-and-verify-site-12184f8b).

### 7.2. Убедитесь, что карта действительно известна Bing

Откройте **Sitemaps**. Если `https://kolosei.com/sitemap-index.xml` уже импортирован и обрабатывается, второй раз добавлять его не нужно. Иначе выберите **Submit sitemaps**, вставьте полный адрес и отправьте. Запишите статус и дату последнего чтения. Позже проверьте одну главную и одну продуктовую страницу инструментом URL Inspection Bing. [Sitemaps в Bing](https://www.bing.com/webmasters/help/sitemaps-3b5cf6ed).

### 7.3. Что уже сделал IndexNow

При публикации сайт отправил уведомление о 34 URL в IndexNow. Ответ **202** означает: уведомление получено, проверка ключа ожидается. Это зафиксировано в [квитанции](../../research/website-discovery/2026-09-08/indexnow-receipt.json). В этой сессии новую отправку не делали.

IndexNow — канал уведомления участвующих поисковых систем об изменении адресов. Он дополняет sitemap. Ни 200, ни 202 не означают «страница проиндексирована» и не подтверждают отправку в Google. Само наличие публичного файла ключа также не доказывает, что сервис завершил его проверку. [Протокол IndexNow](https://www.indexnow.org/documentation).

После содержательного обновления разработчик может использовать готовый скрипт `scripts/submit-indexnow.mjs`: сначала просмотр списка, затем отправка по факту публикации. Ежедневная повторная отправка неизменных страниц не является стратегией продвижения. Настоящее состояние индекса смотрите в кабинетах поисковиков.

## 8. Как измерять результат: словарь и простая воронка

**Основной ориентир на первый период:** растёт число целевых поисковых визитов и доля посетителей, которые переходят в продукт. Когда появится измерение приложения — добавляем первое полезное действие и возвращение к занятиям.

| Показатель | Простыми словами | Где взять |
| --- | --- | --- |
| Показы / Impressions | Как часто результат сайта показывался в поиске | GSC или BWT |
| Клики / Clicks | Сколько переходов совершено из результатов поиска | GSC или BWT |
| CTR | Клики, делённые на показы, в процентах | GSC/BWT или расчёт |
| Средняя позиция | Усреднённое положение результата в наблюдавшихся показах | GSC; анализировать в разрезах |
| Сеансы / Sessions | Посещения, сгруппированные системой аналитики | После установки аналитики |
| Переход в продукт | Нажатие ссылки, ведущей в Студию или Зал | Специальное событие сайта, пока не подключено |
| Активация | Первое заранее определённое полезное действие в приложении | Отдельное измерение приложения |
| Возвращение | Повторная полезная работа той же когорты | Отдельное измерение приложения или добровольное исследование |

Определения поисковых кликов, показов, CTR и средней позиции приведены в [справке Performance](https://support.google.com/webmasters/answer/7576553?hl=en). Средняя позиция всего сайта может ухудшиться, когда появились новые показы по новым запросам; это не обязательно означает ухудшение старых страниц.

### Пример расчёта — условные числа, не данные вашего сайта

За 28 дней получено 1000 показов и 40 кликов. **CTR = 40 / 1000 × 100% = 4%.** Аналитика сайта за тот же период зафиксировала 36 органических сеансов, из которых в 9 был переход в продукт. **Доля сеансов с переходом = 9 / 36 × 100% = 25%.**

40 кликов GSC и 36 сеансов аналитики не обязаны совпадать: это разные системы и способы подсчёта; дополнительно влияют согласие, блокировщики, загрузка страницы, часовые пояса и фильтры. Нельзя объявить «10% пользователей потерялись» только из этого различия.

Если событий перехода 12, но они произошли в 9 сеансах, для доли сеансов берите **9**, а не 12. Один человек мог нажать несколько раз. Если знаменатель равен нулю, пишите «не рассчитывается». При изменении с 0 до 5 кликов пишите «+5 кликов», а не «рост на бесконечность».

### Три панели вместо одного большого числа

- **Техника:** доступность ключевых URL, ошибки, лабораторная скорость, полевые метрики при наличии.
- **Привлечение:** поисковые показы, клики, видимые небрендовые запросы, внешние переходы, ИИ-цитирование.
- **Польза:** сеансы с переходом в продукт, завершённое первое действие, возвращения.

Рост технических баллов без движения второй и третьей панелей — поддержание качества, а не доказанное продвижение.

## 9. Первый отчёт Search Console: пошагово

### 9.1. Настройка вида отчёта

1. Выберите ресурс **`https://kolosei.com/`**.
2. Откройте **Performance → Search results / Эффективность → Результаты поиска**.
3. Оставьте тип поиска **Web / Веб**.
4. Для первого наблюдения задайте доступный период с начала накопления данных. Позже используйте полные 28 дней и сравнение с предыдущими 28 днями.
5. Включите четыре показателя: клики, показы, CTR, средняя позиция.
6. Просмотрите вкладки Queries, Pages, Countries, Devices — запросы, страницы, страны, устройства.

На первом месяце не сравнивайте 5 дней после настройки с 28 днями до неё. Недоступную историю пометьте «нет данных». Самые свежие точки могут быть предварительными. [Настройка Performance](https://support.google.com/webmasters/answer/7576553?hl=en).

### 9.2. Отделите узнаваемость от нового спроса

**Брендовый запрос:** человек уже знает название — например, «LinguistPro Kolosei». **Небрендовый:** ищет решение — например, «как читать иврит с огласовками».

Для простого старта добавьте фильтр запроса «не содержит LinguistPro». Он неполон: не исключает Kolosei и кириллические варианты. Для более аккуратного приближения используйте Custom regex → Doesn't match с выражением:

```text
(?i)linguist\s*pro|kolosei|лингвист\s*про|лингвистпро|колосей
```

Это наш рабочий список вариантов, а не официальный словарь бренда. Корректируйте его по реальным запросам. Не заменяйте «небрендовые клики» разностью общего числа и брендового: часть запросов скрывается. В отчёте называйте показатель **«видимые небрендовые клики по фильтру …»**. [Фильтры и сравнение](https://support.google.com/webmasters/answer/17011165?hl=en), [скрытые запросы и ограничения](https://support.google.com/webmasters/answer/17011259).

Для русского контента добавьте фильтр страницы, содержащей `/ru/`. Язык страницы и страна человека — разные признаки: русскоязычные пользователи могут находиться в Израиле и других странах. На старте не ограничивайте отчёт одной страной без причины.

### 9.3. Что выгрузить и сохранить

Нажмите **Export / Экспорт** и сохраните таблицы запросов и страниц за тот же период. Имя файла делайте понятным, например `gsc-kolosei-ru-web-2026-09-08_2026-10-05`. Отдельно запишите выбранный ресурс, фильтры и дату выгрузки. Суммы строк могут отличаться от общего графика; экспортированные нули иногда соответствуют отсутствовавшему значению. [Экспорт отчёта](https://support.google.com/webmasters/answer/12919797?hl=en).

**Личные выгрузки храните в своей папке отчётов вне публичного GitHub.** В репозитории достаточно обезличенного итога и описания решения. Не публикуйте адрес Google-аккаунта, скриншоты профиля и чувствительные поисковые запросы.

### 9.4. Еженедельный сеанс на 30 минут

| Время | Что сделать | Что записать |
| --- | --- | --- |
| 5 минут | Проверить сообщения и состояние ключевых страниц | Есть ли техническая проблема |
| 10 минут | Посмотреть 5–10 запросов и страниц с наибольшим интересом | Какая тема получает подходящие показы |
| 5 минут | Проверить переходы в продукт, если измерение подключено | Доля сеансов и абсолютные числа |
| 5 минут | Посмотреть доступные Google/Bing ИИ-отчёты | Есть ли новые страницы-источники |
| 5 минут | Выбрать одно изменение на неделю | Гипотеза, действие, дата следующей проверки |

Цель встречи — одно обоснованное решение. Не нужно ежедневно переписывать заголовки из-за колебаний нескольких показов.

## 10. Как увидеть переходы в LinguistPro: аналитика вторым этапом

### 10.1. Что сейчас не измеряется

В проверенных исходниках сайта нет установленного GA4, Google Tag Manager, Plausible или Umami; в проверенном HTML главной не найдены обычные маркеры этих систем и Cloudflare Web Analytics. Политика сайта сообщает об отсутствии сторонней аналитики. Это не аудит всех настроек аккаунта Cloudflare, но оснований считать продуктовые переходы уже измеренными нет.

Поэтому сейчас **«число переходов в Зал неизвестно»**, а не «переходов ноль». Search Console наблюдает выдачу Google и клики из неё; он не считает нажатие вашей кнопки «Начать с готового текста» после открытия сайта.

### 10.2. Рекомендуемый порядок

| Вариант | Что даст | Ограничение | Когда выбрать |
| --- | --- | --- | --- |
| Только GSC + BWT | Поисковые показы, клики, индексация | Не показывает дальнейшее использование | Подключить сейчас |
| Cloudflare Web Analytics | Обзор посещений и качества загрузки | Не принимать за готовую продуктовую воронку; проверить нужные метрики | Если сначала нужен простой обзор |
| GA4 с одним событием перехода | Источники посещений и долю сеансов с переходом в продукт | Нужны установка, проверка и согласованный подход к данным | Рекомендуемый второй этап, если нужно считать воронку |

Cloudflare описывает Web Analytics как бесплатную систему без cookies и сбора персональных данных в рамках её модели измерения. Это характеристика инструмента, а не автоматическое заключение о требованиях для вашего сайта. [Cloudflare Web Analytics](https://developers.cloudflare.com/web-analytics/).

Моя рекомендация: сначала GSC/BWT, затем **одна** система аналитики с минимальным набором событий. Не ставьте одновременно несколько счётчиков «на всякий случай». Сначала определите, какое решение поможет принять каждый собираемый показатель.

### 10.3. Как создать GA4, если вы выбираете этот вариант

1. Войдите в [analytics.google.com](https://analytics.google.com/) тем же постоянным Google-аккаунтом.
2. Выберите начало измерения или создание аккаунта. Название: `Kolosei`.
3. Создайте ресурс, например `Kolosei website`.
4. Выберите часовой пояс отчётов **Asia/Jerusalem / Israel**, если так удобнее вашей работе; валюту — ту, в которой позднее будете считать расходы. Валюта не включает платежи.
5. Создайте поток **Web** для `https://kolosei.com`, имя `Kolosei public website`.
6. Сохраните идентификатор измерения `G-…` и ссылку на ресурс.
7. Передайте разработчику идентификатор и задачу ниже. Само создание ресурса ещё не устанавливает счётчик на сайт.

[Официальная настройка GA4](https://support.google.com/analytics/answer/9304153?hl=en). Меню может меняться; ищите Admin / Администратор, Data streams / Потоки данных, Web.

Перед публикацией аналитики нужно определить состав данных и поведение при согласии/отказе применительно к вашей аудитории, обновить политику и проверить реализацию. Это отдельное изменение продукта; данное руководство ничего не установило. Конкретные правовые требования зависят от условий работы и здесь не устанавливаются.

### 10.4. Готовое задание разработчику

```text
Задача: минимальное измерение переходов с kolosei.com в LinguistPro.

1. Подключить выбранную аналитику один раз в общем шаблоне сайта.
2. Создать явное событие product_open при реальном нажатии ссылки
   на linguistpro.kolosei.com, включая ссылки конкретных корпусов.
3. Параметры: destination = studio | reading_room;
   placement = hero | product | guide | footer | other;
   locale = ru | en; page_path = очищенный путь страницы витрины.
4. Передавать только разрешённые значения. Исключить тексты пользователя,
   email, ключи, содержимое документов и произвольные query-параметры.
5. Не отправлять событие при загрузке страницы, наведении или автопереходе.
6. Проверить одно событие на одно нажатие мышью и клавиатурой;
   не терять его из-за навигации и не задерживать открытие продукта.
7. Проверить согласие/отказ согласно выбранной политике и отсутствие дублей.
8. Проверить событие в DebugView/Realtime и затем в обычном отчёте.
9. Отчёт: сеансы organic search и сеансы organic search с product_open,
   отдельно по destination и странице входа.
10. Повторить браузерную проверку и Lighthouse после установки.
```

`product_open` — предлагаемое нами пользовательское событие, а не уже существующая функция сайта и не стандартное название Google. GA4 поддерживает пользовательские события; параметры, нужные для регулярных разрезов, разработчик регистрирует и проверяет в отчётах. [Настройка событий](https://developers.google.com/analytics/devguides/collection/ga4/events).

Не полагайтесь только на автоматический `click`: автоматические исходящие клики зависят от доменов и конфигурации междоменного измерения. Переход на собственный поддомен необходимо проверить явно. [Enhanced measurement](https://support.google.com/analytics/answer/9216061?hl=en).

### 10.5. Как владельцу принять измерение

Откройте сайт, выполните оговорённый тестовый сценарий, нажмите кнопку Зала один раз. В Realtime/DebugView должно появиться ровно одно ожидаемое событие с правильным назначением. Повторите для Студии и ссылки на конкретный корпус. После появления события его можно отметить как **Key event / Ключевое событие**. Это маркирует важность измерения, но не создаёт отсутствующий обработчик клика. [Ключевые события GA4](https://support.google.com/analytics/answer/13128484?hl=en).

Попросите итоговый скриншот с параметрами теста, но без личных данных. Затем проверяйте обычные отчёты за полный период: Realtime — диагностика, а не месячная статистика. Тестовые визиты владельца желательно отделить от пользовательских.

**Следующая ступень:** событие в приложении после успешного открытия учебного текста и первого действия с ним. Сайт-витрина самостоятельно этого не видит. Аналитика приложения, связывание сеансов между поддоменами и измерение возвращений требуют отдельного проекта. До него не называйте `product_open` «новым активным учеником».

### 10.6. Где смотреть результат в GA4

После настройки откройте **Reports → Acquisition → Traffic acquisition / Отчёты → Привлечение → Привлечение трафика**. Если такого пункта нет, редактор ресурса может добавить отчёт в навигацию.

1. Выберите тот же законченный период, который используете для своего журнала.
2. В группировке сеансов найдите **Organic Search** — бесплатный поисковый трафик. Для одного Google переключитесь на **Session source / medium** и найдите `google / organic`.
3. Запишите **Sessions / Сеансы**.
4. В показателях ключевых событий выберите именно `product_open`, если доступен выбор события. Смотрите **Session key event rate** — долю сеансов с этим событием.
5. Если нужного разреза нет, попросите разработчика сохранить отдельный отчёт для `product_open`; не подставляйте общую долю всех ключевых событий.

Показатель **Key events** считает срабатывания, а не сеансы. Чтобы получить точное число сеансов с переходом, используйте подготовленный отчёт; обратный расчёт из округлённого процента даёт лишь приближение. [Traffic acquisition GA4](https://support.google.com/analytics/answer/12923437?co=GENIE.Platform%3DDesktop&hl=en).

Не смешивайте этот отчёт с User acquisition: тот отвечает на вопрос о первом привлечении пользователя. При повторных визитах это разные разрезы. [Различие отчётов](https://support.google.com/analytics/answer/14731736).

## 11. Как поддерживать скорость, доступность и SEO

### 11.1. Проверка без командной строки

1. Откройте [PageSpeed Insights](https://pagespeed.web.dev/).
2. Вставьте `https://kolosei.com/ru/` и запустите анализ.
3. Сначала посмотрите **Mobile**, затем **Desktop**.
4. Различайте верхний блок реальных пользователей и нижний лабораторный анализ.
5. Запишите дату, URL, устройство, четыре оценки и проблемные пункты.
6. Повторяйте для страницы, которую существенно изменяли; раз в месяц — для главной, двух продуктов и одной статьи в нужных языках.

Если оценка неожиданно упала, выполните ещё два сопоставимых прогона и посмотрите медиану, а не выбирайте лучший. PageSpeed может отличаться от сохранённого локального Lighthouse из-за среды и версии. Отсутствие полевых данных означает, что доступной выборки недостаточно; это не равно провалу. [Как работает PageSpeed Insights](https://developers.google.com/speed/docs/insights/v5/about).

### 11.2. Какие реальные показатели важнее круглого числа

| Полевой показатель | Что ощущает человек | Хороший порог |
| --- | --- | --- |
| LCP | Быстро ли появился основной контент | Не более 2,5 с |
| INP | Быстро ли интерфейс отвечает на действия | Не более 200 мс |
| CLS | Не прыгает ли содержимое при загрузке | Не более 0,1 |

Оценка применяется на 75-м процентиле: не менее 75% учитываемых посещений должны укладываться в порог. Смотрите мобильные и настольные данные отдельно. Полевые отчёты используют накопленные данные, а не один ваш запуск. **TBT 0 не доказывает INP 0**: это разные показатели. [Core Web Vitals](https://web.dev/articles/vitals).

### 11.3. Наши рабочие сигналы для действий

Это внутренние ориентиры проекта, не требования Google:

| Наблюдение | Решение |
| --- | --- |
| Performance колеблется в пределах 95–100, явных проблем нет | Продолжать контентную работу, не тратить день на 98 → 100 |
| Повторяемое падение медианы на 5+ пунктов после конкретного изменения | Проверить новую картинку, видео, шрифт или скрипт |

| Полевые LCP/INP/CLS вышли из хорошего диапазона при достаточных данных | Исследовать реальную проблему по устройствам и страницам |
| Новый noindex, 404 на важной странице, неверный canonical | Разобрать в первую очередь |

### 11.4. Как сохранить достигнутое

- Добавлять изображения подходящего размера и задавать их ширину/высоту.
- Не ставить тяжёлое автоматически запускаемое видео на первый экран.
- Подключать внешние скрипты только с понятной пользой и проверкой влияния.
- После изменения проверить телефон, увеличение текста, Tab/Enter, ссылки и раскрывающиеся блоки.
- Проверять смысл заголовков, подписи кнопок и альтернативные тексты изображений.
- Сохранять стабильные URL. При переименовании страницы делать осмысленный постоянный редирект.
- Проверять языковые соответствия; русская страница не должна ошибочно объявлять английскую своей канонической копией.

В проекте уже есть `npm run build`, `npm run verify` и `npm run verify:browser`. После исправлений разработчик использует их по существующей инструкции репозитория. Не нужно заново запускать весь набор только потому, что вы открыли поисковый кабинет.

## 12. Что публиковать: стратегия для LinguistPro

### 12.1. Начните с узких задач аудитории

Для первого цикла я рекомендую русскоязычных учащихся иврита, которым нужен переход от отдельных слов к чтению, и студентов, которым нужен технический иврит. Английские версии сохраняем и развиваем по данным. Это рабочая гипотеза из возможностей продукта, а не измеренная оценка рынка.

Узкая задача «прочитать песню с огласовками и переводом» ближе к текущему продукту, чем попытка немедленно победить всех по запросу «учить иврит». Исследуйте реальные формулировки в GSC/BWT и разговорах с учащимися. Не приписывайте предлагаемым словам частотность, которой мы не измеряли.

| Намерение человека | Запрос-гипотеза | Страница для работы | Полезный следующий шаг |

| Начать читать | «как читать иврит с огласовками» | Существующий гид hebrew-reading | Открыть короткий подготовленный текст |

### 12.2. Сначала улучшайте существующие страницы

По каждому гиду добавьте один реальный, воспроизводимый учебный сценарий. Например: «разберите четыре строки, сначала с поддержкой, затем без неё». Покажите проверенный пример, точное действие и честное ограничение. Не обещайте научно подтверждённую эффективность, если есть только техническая проверка.

У продукта есть материал, который трудно заменить общим пересказом: реальные экраны, разбор учебной ситуации, понятная граница готового и нового облачного контента. Используйте это преимущество. Google рекомендует полезное содержание с собственным опытом и самостоятельной ценностью. [People-first content](https://developers.google.com/search/docs/fundamentals/creating-helpful-content).

### 12.3. Шаблон хорошей страницы

1. Чёткий вопрос читателя в заголовке.
2. Короткий ответ и обозначение, кому подходит способ.
3. Один качественный пример на иврите с проверенным объяснением.
4. Пошаговая практика в LinguistPro.
5. Ограничения: уровень, необходимость интернета/ключа, доступность материала.
6. Ссылка на подходящий корпус или инструмент.
7. Ответы на 2–4 настоящих вопроса читателей.
8. Автор, дата содержательной проверки и источники там, где они нужны.

Нет обязательного объёма «2000 слов для Google». Завершите задачу читателя, не растягивая текст. Один намеренный материал лучше нескольких почти одинаковых страниц. Внешние источники и понятные внутренние ссылки помогают читателю проверить и продолжить работу. [SEO Starter Guide](https://developers.google.com/search/docs/fundamentals/seo-starter-guide).

### 12.4. Что считать выполненной публикацией

Публикация готова, когда проверены факты и язык, страница открывается на телефоне, её легко найти из существующих страниц, следующий шаг работает, sitemap обновлён и дата изменения записана в журнал. `lastmod` должен отражать содержательную правку; не обновляйте дату ежедневно ради видимости свежести.

Не копируйте целиком чужие песни или учебники ради поискового трафика. Используйте материалы в пределах подтверждённых прав, собственные примеры и ссылки на опубликованные корпуса. Не добавляйте неподтверждённые отзывы, рейтинги и сравнительные проценты качества.

## 13. Продвижение в ИИ: что реально делать и как проверять

### 13.1. Что уже подготовлено

На сайте есть [человеческая справка](https://kolosei.com/ru/agents/), [JSON-факты](https://kolosei.com/facts/linguistpro.json), [краткий llms.txt](https://kolosei.com/llms.txt) и [полный Markdown](https://kolosei.com/llms-full.txt). Они помогают получить согласованное описание продукта. Основные факты формируются из `src/data/linguistpro.ts`.

Эти файлы не являются заявкой на первое место в ответе модели. Google прямо сообщает, что для его поиска не нужны специальные AI-файлы или Markdown. Значимы полезное содержание, доступность и обычная поисковая структура. [Руководство Google по ИИ-поиску](https://developers.google.com/search/docs/fundamentals/ai-optimization-guide).

### 13.2. Различайте системы и режимы

| Система | Практическое действие | Что это не доказывает |
| --- | --- | --- |
| Google AI Overviews / AI Mode | Индексация, доступность сниппета, проверка Search generative AI в GSC | Что Gemini-приложение обязательно порекомендует продукт |
| ChatGPT с поиском | Доступность для OAI-SearchBot и проверка фактических ссылок в ответе | Что ответ без веб-поиска знает последнюю версию |
| Claude с веб-поиском | Доступность для Claude-SearchBot и проверка цитат | Универсальную совместимость MCP |
| Gemini Apps | Отдельные контрольные вопросы с веб-источниками | Тождество отчёту Google Search |
| Bing / Copilot | BWT, индексация и доступный AI Performance | Полную статистику всех ИИ-систем |

OAI-SearchBot обслуживает поиск; GPTBot связан с обучением моделей; ChatGPT-User — с отдельными действиями пользователя. Это разные механизмы. [OpenAI Crawlers](https://developers.openai.com/api/docs/bots). Аналогично Anthropic разделяет Claude-SearchBot, Claude-User и ClaudeBot. [Справка Anthropic](https://support.claude.com/en/articles/8896518-does-anthropic-crawl-data-from-the-web-and-how-can-site-owners-block-the-crawler).

У Google-Extended отдельная роль: управление некоторыми сценариями обучения и grounding Gemini; он не является сигналом ранжирования Google Search. Поэтому не переносите на Gemini правила, прочитанные только про ChatGPT. Текущий permissive robots сайта не менялся при подготовке руководства. [Google-Extended](https://developers.google.com/crawling/docs/crawlers-fetchers/google-common-crawlers#google-extended).

### 13.3. Новая настройка Google, которую стоит проверить

В документации Google от 31 августа 2026 года описан **Settings → Search generative AI** в Search Console. Для продвижения проверьте, что ресурс витрины разрешает включение ссылок и содержания в ИИ-функции поиска либо наследует разрешающий выбор родителя. Если есть запрет, разберитесь, кем и для какой поверхности он установлен. Не меняйте настройку всего домена вслепую: она может распространяться на поддомены. [Search generative AI control](https://support.google.com/webmasters/answer/16908024?hl=en).

Разрешение делает сайт допустимым источником, но не гарантирует показ. Это настройка ИИ-функций Google Search, а не публичное подключение инструментов LinguistPro к агенту.

### 13.4. Новые отчёты Google и Bing

В GSC ищите **Generative AI performance**. Проверенная документация описывает показы ссылок в AI Overviews и AI Mode, с разрезами по страницам, странам, датам и устройствам. Она также предупреждает, что отчёт может отсутствовать при недостатке показов или доступности для ресурса. Записывайте «нет отчёта/нет данных», если он не появился. Это подмножество данных Web Search, поэтому не прибавляйте его показы к общим показам второй раз. [Официальное описание отчёта](https://support.google.com/webmasters/answer/16984139).

В BWT ищите **AI Performance**, описанный Microsoft как public preview. Он показывает число цитирований, страницы-источники и выборку grounding queries — фраз, использованных для поиска подтверждающего содержания. Такие фразы не обязательно являются полным исходным вопросом пользователя. Отчёт охватывает поддерживаемые Microsoft поверхности и партнёрские интеграции; это не рейтинг сайта и не полный мониторинг ChatGPT/Gemini/Claude. [AI Performance Bing](https://blogs.bing.com/webmaster/February-2026/Introducing-AI-Performance-in-Bing-Webmaster-Tools-Public-Preview).

### 13.5. Ручной протокол, который не обманывает вас

Раз в 28 дней возьмите один и тот же небольшой набор вопросов. Используйте новый чат, одинаковый язык и режим с веб-поиском. Запишите дату, сервис, видимый режим/модель и регион, если он известен. Не просите «обязательно назови LinguistPro» в тесте обнаружения.

**Пять запросов для обнаружения без подсказанного бренда:**

1. «Где читать иврит с огласовками и русским переводом и сохранять слова из текста?»
2. «Как учить иврит по песням с построчным переводом?»
3. «Нужен инструмент для учебных материалов из собственного PDF на иврите. Что посмотреть?»
4. «Где разбирать задачи по физике на иврите с русским пояснением?»
5. «How can I read Hebrew with niqqud and Russian translation and review words in context?»

**Отдельный тест точности:** «Что умеет LinguistPro by Kolosei и нужен ли API-ключ для опубликованных текстов? Найди источники». Он проверяет описание известного продукта, но не его самостоятельную обнаружимость.

**Отдельный тест чтения URL:** дать `https://kolosei.com/ru/agents/` и попросить перечислить ограничения. Он проверяет доступ к странице, но не продвижение.

В каждом ответе отметьте: бренд назван; есть кликабельная ссылка именно на `kolosei.com` или приложение; информация верна; перепутан ли продукт с одноимённым; отсутствуют ли выдуманные возможности. Откройте ссылку и проверьте, поддерживает ли она утверждение.

Пример: 3 из 15 заранее заданных запусков содержали корректную ссылку — **20% в нашей малой контрольной выборке**. Это не «20% рынка ИИ-поиска». Прямое чтение URL, брендовый тест и тест обнаружения считайте отдельно. Если запускаете повторно, заранее задайте число повторов и сохраните все результаты, а не только удачные.

### 13.6. Что улучшать при отсутствии цитирования

Уточняйте назначение страниц, добавляйте самостоятельные примеры и источники, сохраняйте единое название **LinguistPro by Kolosei**, исправляйте устаревшие факты. Добивайтесь содержательных внешних упоминаний от реальных пользователей и преподавателей. Посещение роботом, наличие JSON-LD и чтение llms.txt по прямой ссылке сами по себе не подтверждают рекомендации модели.

MCP/OAuth остаётся отдельным владельческим пилотом. Не рекламируйте общедоступную интеграцию ChatGPT/Claude/Gemini, пока нет соответствующего опубликованного продукта и проверок.

## 14. Смежное продвижение: доверие, сообщества и конверсия

### 14.1. Практический план внешних упоминаний

Начните с мест, где уже обсуждают задачи вашей аудитории: преподаватели иврита, учебные группы, сообщества студентов, авторы материалов о чтении и языковых инструментах. Составьте список 10 подходящих контактов, изучите правила площадок и подготовьте персональные сообщения. В этой работе сообщения никому не отправлялись.

Предлагайте конкретную пользу: короткий практикум по песне, демонстрацию чтения задачи или тестирование сценария урока. Раскрывайте, что вы автор продукта. Просите честную обратную связь; не ставьте положительный отзыв условием доступа.

Черновик обращения: «Я разрабатываю LinguistPro для чтения иврита с поддержкой. Подготовил короткий пример для вашей учебной задачи. Если это уместно для вашей группы, буду рад показать его и узнать, что непонятно учащимся». Затем дайте ссылку на подходящий гид, а не обязательно на главную.

### 14.2. Как различать источники переходов

Для внешних публикаций можно использовать UTM-метки. Например:

```text
https://kolosei.com/ru/guides/hebrew-through-songs/?utm_source=telegram&utm_medium=community&utm_campaign=hebrew_songs_2026_09
```

`source` — площадка, `medium` — тип размещения, `campaign` — конкретная инициатива. Это пример будущей кампании; переходов по нему ещё не измеряли. Используйте единый регистр и названия. Не добавляйте UTM к внутренним ссылкам сайта и переходам в своё приложение для измерения собственных кнопок: для них предназначено событие. UTM дают отчёт только там, где их принимает установленная аналитика. [Параметры кампаний GA4](https://support.google.com/analytics/answer/10917952?hl=en).

### 14.3. Что повысит доверие

- Понятное имя автора, контакты, работающая обратная связь.
- Реальные демонстрации с датой проверки, включая мобильный экран.
- Короткое объяснение: что бесплатно доступно без своего ключа и где возникает облачная обработка.
- Проверенные педагогические примеры без обещаний гарантированного уровня языка за срок.
- Согласованное описание продукта на сайте, GitHub, в видео и доступных профилях автора.
- Проверка пути нового человека: переход из статьи → Зал → выбранный материал, без необходимости понимать инфраструктуру.

Не покупайте пакеты ссылок и «гарантированное попадание в GPT». Не публикуйте сотни почти одинаковых статей и фальшивые отзывы. Не создавайте фиктивную локальную компанию с выдуманным адресом ради карт. Платные кампании стоит тестировать после проверки измерения и первого пользовательского пути; их бюджет и критерий остановки задаются отдельно.

### 14.4. Другие каналы — по реальному спросу

Если отчёты покажут существенную аудиторию из конкретной поисковой системы или страны, добавьте её инструменты и локальный контент следующим этапом. На старте достаточно Google и Bing, качественных русских/английских страниц и небольшого числа подходящих сообществ. Ивритскую версию сайта имеет смысл расширять при возможности качественного языкового сопровождения и доказанном запросе аудитории.

## 15. Календарь на 90 дней и критерии результата

Отсчитывайте день 1 от фактической настройки кабинетов. Если старт 8 сентября, первые полные 28 дней — 8 сентября–5 октября, второй период — 6 октября–2 ноября. Сравнение выполняйте после того, как законченные данные появятся в отчётах. Даты выгрузки и часовые пояса записывайте отдельно.

| Период | Работа | Проверяемый результат |
| --- | --- | --- |
| Дни 1–3 | GSC, домен, префикс, sitemap, Bing | Подтверждение владения и записанные статусы обеих карт |
| Дни 4–7 | Проверка шести приоритетных URL, исходный журнал | Для каждого URL известен статус или конкретная причина ожидания |
| Неделя 2 | Выбор аналитики, проверка события перехода, 2–3 добровольных пользовательских прохода | Измерение проверено либо явно записано, что переходы пока неизвестны |
| Недели 3–4 | Улучшить один гид и одну продуктовую страницу, получить несколько содержательных отзывов | Опубликованные изменения и журнал обратной связи |
| После 28 дней | Первый полный отчёт GSC/BWT и контроль ИИ | Честная исходная картина, один выбранный узкий приоритет |
| Дни 29–56 | Развивать лучший сценарий; 1–2 содержательные публикации или улучшения | Есть новая проверяемая гипотеза и результаты сопоставимых периодов |
| После 56 дней | Сравнить два полных периода, оценить переходы и затраты | Решение: продолжить тему, улучшить путь или сменить гипотезу |
| Дни 57–90 | Повторить успешный подход, аккуратно расширить канал | Устойчивый источник подходящих посетителей либо документированная причина пересмотра |

### Что считать эффективностью, когда ещё нет базовой статистики

Не назначайте сейчас универсальную норму «1000 кликов за месяц». Сначала установите наблюдаемый спрос. Для первого цикла зафиксируйте цели, которые зависят от ваших действий:

- Все выбранные приоритетные страницы технически доступны, а их индексный статус разобран.
- Есть два сопоставимых отчётных периода или явно обозначено, что второй ещё не накоплен.
- Появились подходящие небрендовые запросы, по которым можно принять контентное решение.
- Настроено и проверено измерение перехода, если вы выбрали аналитику.
- Есть хотя бы один подтверждённый пользовательский сценарий и понятное улучшение по обратной связи.

После первого полного периода поставьте численную цель на следующий. **Пример, не прогноз:** если было 40 целевых кликов и 8 органических сеансов с переходом, рабочая цель может быть 50 кликов и 10 таких сеансов при сохранении качества аудитории. Показатели кликов и сеансов ведите раздельно. При малых числах такой рост — сигнал для дальнейшей проверки, а не статистически доказанная причинность.

Если за 56 дней почти нет показов, сначала проверьте индексацию, попадание в потребность и содержание страниц. Если показы есть, а кликов мало — анализируйте запрос, заголовок и позицию. Если переходы есть, а пользы нет — исследуйте приложение и первый сценарий. Дальнейшие действия зависят от места потери.

## 16. Как принимать решения по цифрам

| Наблюдение | Возможное объяснение | Что сделать первым | Чего не заключать |
| --- | --- | --- | --- |
| Нет показов | Нет индексации, мало спроса, новая страница | Проверить URL и соответствие теме | «Дизайн плохой» |
| Показы растут, клики нет | Новые запросы, слабый сниппет, низкие позиции | Разобрать конкретные запросы и страницы | «Надо увеличить плотность ключей» |
| Хорошая позиция, мало кликов | Намерение не совпадает, ответ уже виден в выдаче | Посмотреть реальную выдачу и уточнить обещание страницы | «CTR обязан быть фиксированным процентом» |
| Клики растут, переходы в продукт нет | Слабый следующий шаг или неисправное измерение | Проверить событие и пройти путь пользователя | «Поисковый трафик бесполезен» |
| Много переходов, мало активаций | Сложный вход, неподходящий материал, незнакомые требования | 2–3 наблюдаемых пользовательских прохода | «Нужно ещё больше рекламы» |
| ИИ цитирует, трафика мало | Ответ удовлетворил запрос без перехода | Смотреть цитирование и визиты отдельно | «Цитата равна клиенту» |
| Показатель скачет при 5–10 визитах | Слишком малая выборка | Увеличить период, сохранить абсолютные числа | «Гипотеза уже доказана» |

Меняйте одну важную вещь за раз: например, заголовок конкретного гида. Запишите дату и гипотезу, дайте накопиться сопоставимым данным. При небольшом трафике последовательное наблюдение обычно полезнее сложного A/B-теста с недостаточной выборкой.

## 18. Нагрузка, расходы и помощь специалиста

Для старта достаточно бесплатных поисковых кабинетов, PageSpeed и обычной личной таблицы. Не покупайте большой SEO-сервис до того, как понимаете, какого ответа не хватает в бесплатных инструментах.

Реалистичный рабочий ритм для одного владельца: 30 минут на отчёт, 1–2 часа на полезное улучшение материала и до часа на обратную связь/распространение в неделю. Это план нагрузки, а не норматив. Если времени мало, делайте один хороший материал раз в две недели и сохраняйте регулярность измерения.

Разработчик нужен для подключения событий, технических ошибок, изменений шаблонов, редиректов и публикации. Преподаватель или компетентный редактор — для языковой и педагогической проверки. SEO-специалист становится полезен, когда уже есть данные и конкретная задача: например, страницы проиндексированы, но релевантных показов мало.

Просите у специалиста конкретные действия, доказательства, отчёт по вашим целевым URL и понятную метрику. Проверяйте, что аккаунты принадлежат вам и результаты сохраняются. Не принимайте «подняли внутренний SEO-score» за единственное подтверждение пользы работы.

## 19. Если нужен совсем короткий порядок действий

**Сегодня:** Google-аккаунт → доменный ресурс → TXT Cloudflare → ресурс витрины → sitemap → проверка трёх главных страниц.

**Завтра:** Bing → импорт → проверка карты → ещё три гида → паспорт настройки.

**На следующей неделе:** выбрать измерение переходов, проверить первый пользовательский путь и улучшить один материал.

**Каждую неделю:** 30 минут на данные и одно содержательное действие.

**Через 28 и 56 дней:** сопоставимый отчёт, проверка ИИ-цитирования и решение на следующий цикл.

Ваш основной вопрос: **«Какая страница приводит подходящего человека к первому полезному действию, и чем это подтверждается?»** Ответ на него важнее повторного достижения круглой оценки Lighthouse.
